# Measuring the contribution of Limen to engineering

Do not assume the method is superior because it produces more reasoning, agents, tests or documents.

For a controlled pilot, compare at least: **A. conventional engineering; B. ordinary AI-assisted engineering; C. Limen-guided AI engineering**. To isolate Limen from generic structured engineering, add **D. AI-assisted engineering with ordinary engineering quality gates but without Limen-specific formation and correction practices**.

Match task scope, developer expertise, tool access, environment, model budget and test difficulty. Prefer preregistered held-out tests that implementation agents cannot see. Include negative findings and tests that show the method did not add value.

Measure independently observed defect rate/severity, security boundary violations, maintainability under a subsequent change, rollback/recovery effectiveness and engineering cost. TCO includes human labor for supervision, compliance evidence, tests, rework, inference and local compute. Explicitly separate security effectiveness from administrative compliance.

A result that improves quality on one project does not prove broad statistical superiority. Label all exploratory analyses as such. A useful null result is that competent conventional or standard AI-assisted engineering already delivers equivalent quality at lower cost.
